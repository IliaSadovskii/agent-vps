## Команды на сервере

- `claude-new <имя> [папка]` — создать сессию В ТЕКУЩЕЙ ПАПКЕ (наследует папку, где идёт разговор). Из основной управляющей (ops) → управляющая сессия в ops. Изнутри проекта → дочерняя сессия в папке этого проекта. Вторым аргументом можно задать папку явно — `claude-new kit-2 /projects/agent-kit`; через `cd` это не работает, папка берётся у tmux-панели родителя. Имя в приложении зависит от папки: вне `/projects` — `vps-<имя>`, внутри проекта — `proj-<проект>-<имя>` (если имя уже начинается с проекта — просто `proj-<имя>`). Команда печатает готовое имя — его и называй пользователю. Закрывается сессия по короткому имени, а не по тому, что видно в приложении.
- `claude-project <имя> [github-url]` — создать/переоткрыть проект в `/projects/<имя>` (главная сессия проекта, `proj-<имя>`). Если дана github-ссылка — репозиторий клонируется в папку проекта.
- `claude-list` — показать все живые сессии и память каждой.
- `claude-close [имя]` — закрыть сессию. БЕЗ имени — текущую. С именем — названную (ищет и побочные, и проекты). Основную (vps-main) нельзя.
- `claude-close-all` — закрыть только ПОБОЧНЫЕ сессии (временные управляющие + дочерние). Главные сессии проектов и vps-main остаются.
- `claude-close-everything` — закрыть ВСЁ, включая главные сессии проектов. Остаётся только vps-main. Папки проектов на диске целы.
- `claude-ssh [имя]` — показать готовую команду подключения к терминалу сессии из компьютера. Без имени — текущая; `main` — основная; имя — проект или побочная.

## Как реагировать

**«создай сессию для отладки nginx»** (управление сервером) → `claude-new nginx`. Сессия появится в текущей папке. Скажи, что vps-nginx создана.

**«открой параллельную сессию для проекта X»** (проект уже открыт, нужна вторая) → `claude-new <X>-2 /projects/<X>`. В приложении она будет `proj-<X>-2`, рядом с главной `proj-<X>`. Закрыть: `claude-close <X>-2`.

**«создай проект shop» / «заведи проект под магазин»** → `claude-project shop`. Создастся /projects/shop и главная сессия проекта (proj-shop). Если проект уже был — переоткроется, код не теряется.

**«создай проект»** (БЕЗ имени и деталей) → ВЕДИ ДИАЛОГ. КРИТИЧЕСКИ ВАЖНО: собери
СНАЧАЛА обе вещи (имя И ссылку), и только ПОТОМ вызывай команду ОДИН раз. НЕ
создавай проект после получения только имени — если создать сессию до
клонирования, скиллы из репозитория НЕ загрузятся (сессия читает их при старте).
  1. Спроси: «Как назвать проект?» — дождись ответа, преобразуй в латинское имя (магазин→shop).
  2. Спроси: «Есть GitHub-репозиторий? Пришли ссылку — склонирую сразу. Или "нет" — создам пустой.» — ДОЖДИСЬ ответа.
  3. ТЕПЕРЬ (получив оба ответа) вызови команду ОДИН раз:
     - дали ссылку → `claude-project <имя> <url>` (клонирует ДО старта сессии — скиллы репо загрузятся);
     - сказали "нет" → `claude-project <имя>` (пустой проект).
  4. Сообщи результат: проект создан/склонирован, сессия появилась в приложении.

ПОЧЕМУ порядок важен: команда `claude-project <имя> <url>` клонирует репозиторий
ДО запуска сессии, поэтому скиллы из `.claude/skills/` репозитория загружаются
при старте. Если же создать пустой проект, а потом клонировать внутрь живой
сессии — её скиллы уже загружены (без репозитория), и `/skill` из репо не виден
до перезапуска проекта.

**«создай проект shop из github.com/me/shop»** (всё сразу) → пропусти вопросы, сразу `claude-project shop https://github.com/me/shop`.

**«открой проект shop» / «вернись к проекту shop»** → `claude-project shop` (переоткрывает существующий).

**Если скилл/команда из репозитория проекта не видны** (например, репозиторий склонировали в уже работающую сессию) → сначала попробуй `/reload-skills` (пересканирует скиллы без потери контекста). Если не помогло (папки `.claude/skills/` не было на момент старта сессии — тогда reload её не подхватит), нужно переоткрыть проект: `claude-close <имя>` затем `claude-project <имя>`. Свежая сессия загрузит скиллы репозитория при старте. Код на диске цел. ЛУЧШЕ вообще не попадать в эту ситуацию — клонировать сразу через `claude-project <имя> <url>`, тогда скиллы грузятся с первого старта.

**«закройся»** → `claude-close` без аргумента (закроет текущую). Не в vps-main.

**«закрой сессию nginx»** → `claude-close nginx`.

**«закрой лишние/побочные сессии»** → `claude-close-all` (проекты остаются).

**«закрой вообще всё» / «выгрузи все проекты тоже»** → `claude-close-everything` (остаётся только vps-main; папки целы).

**«какие сессии открыты» / «сколько памяти»** → `claude-list`.

**«как подключиться к терминалу этой сессии» / «дай ssh-команду» / «хочу зайти в терминал»** → `claude-ssh` (без имени — текущая сессия, или с именем нужной). Покажи пользователю готовую строку `ssh …`, которую он скопирует в терминал компьютера. Объясни, что это подключит к той же живой сессии в полноценном терминале (без ограничений приложения).

## Логика папок (важно понимать)

- Основная `vps-main` живёт в `~/ops` — она управляет сервером.
- `claude-new` порождает ПОБОЧНУЮ сессию В ТОЙ ЖЕ папке, где вызвана. Из ops → в ops. Из проекта → в папке проекта (дочерняя).
- `claude-project` — заводит/переоткрывает проект в `/projects/<имя>`, это ГЛАВНАЯ сессия проекта (бережётся при close-all).

## Иерархия закрытия (важно)

- Побочные (созданные claude-new) — временные, закрываются легко. В приложении они
  называются vps-* или proj-<проект>-* — по папке; тип от имени не зависит.
- Главные проектов (proj-*) — долгоживущие, close-all их бережёт, close-everything закрывает.
- vps-main — никогда не закрывается.
- Закрытие любой сессии НЕ удаляет файлы/папки — только выгружает из памяти. Проект переоткрывается через claude-project.

## Важно

- НЕ создавай сессию, если пользователь хочет просто очистить контекст — для этого /clear.
- Имя — только латинские буквы, цифры, дефис.
- Простаивающие сессии сами закрываются через 7 дней (автоочистка).
