# vps — сервер для разработки с Claude Code

Превращает чистый Ubuntu VPS в машину, где **агенты Claude Code живут постоянно** и
разрабатывают твои проекты. Сессии переживают перезагрузку, доступны из мобильного
приложения и по SSH. Проекты поднимаются в docker и наружу не торчат.

Одна управляющая сессия обслуживает сервер, у каждого проекта — своя сессия в своей
папке. Работают параллельно и не мешают друг другу.

## Установка

Нужен Ubuntu 22.04/24.04 и SSH-ключ у root.

```bash
ssh root@<IP>
git clone https://github.com/IliaSadovskii/vps.git && cd vps
sudo bash init.sh
```

Дальше просто повторяй `bash init.sh`. Он показывает чеклист, делает следующий шаг и
останавливается, когда нужен ты — войти в браузере или перезайти по SSH:

```
  ✔ 1. Сервер: пользователь, безопасность, пакеты
  ▶ 2. Вход в Claude Code
  · 3. Вход в GitHub
  · 4. Автозапуск управляющей сессии
  · 5. Платформа: docker, tailscale
  · 6. Подключение к сети Tailscale
```

Всего три входа в браузере: Claude Code (по подписке, не по API-ключу), GitHub и Tailscale.
Повторный запуск безопасен на любом шаге.

Под конец поставь [клиент Tailscale](https://tailscale.com/download) на ноутбук и телефон
и войди тем же аккаунтом — сервер наружу закрыт, это единственный путь к проектам.
В [консоли Tailscale](https://login.tailscale.com) включи **Serve**, чтобы проекты
открывались по HTTPS.

## Первый проект

```bash
claude-project shop https://github.com/me/shop   # склонировать и открыть сессию
```

Нужны порты — заведи блок и запусти `init.sh` снова:

```bash
cat > ports/shop.env <<'EOF'
# shop — блок 8030-8039
APP_PORT=8030
DB_PORT=8031
EOF
bash init.sh
```

Дальше в сессии проекта: `make up`, `make test`.

## Как устроено

Три слоя. Хост занимается только инфраструктурой, всё специфичное приходит из
репозитория проекта — поэтому проект на любом стеке не требует править сервер.

| Слой | Что даёт | Ставит |
|---|---|---|
| **Сервер** | пользователь `dev`, SSH по ключу, Claude Code, сессии | `setup-server.sh` |
| **Платформа** | docker, tailscale, firewall, порты | `setup-dev.sh` |
| **Проект** | своя БД, свой рантайм, свои версии | `docker-compose.yml` проекта |

`init.sh` вызывает эти скрипты в нужном порядке — руками их запускать не нужно.
Скрипта два намеренно: первый отвечает за вход на сервер, и его поломка стоит доступа.

## Правила проектов

Проекты обязаны соблюдать [контракт](docs/PROJECT-CONTRACT.md): `Makefile` с целями
`up`/`down`/`test`, порты через переменные, `.env.example` без секретов.

Агенты узнают правила сами: Claude Code читает `CLAUDE.md` вверх по дереву каталогов,
поэтому правила лежат в `/projects/CLAUDE.md` и видны любой сессии проекта вместе с его
личным `CLAUDE.md`. Текст — в `templates/projects-CLAUDE.md`, разливается запуском `init.sh`.

Чтобы агент привёл проект в порядок, скажи ему в сессии проекта: «приведи проект к
контракту сервера» — путь к документу он уже знает.

## Сессии

| Имя | Роль | Папка |
|---|---|---|
| `vps-main` | управление сервером, не закрывается | `~/vps` |
| `proj-<имя>` | главная сессия проекта | `/projects/<имя>` |
| `vps-<имя>` | побочная задача | текущая папка |

Каждая команда работает и слэшем в сессии, и обычной фразой, и в терминале.

| Слэш | CLI | Действие |
|---|---|---|
| `/vps-project` | `claude-project <имя> [url]` | проект в `/projects`, с url — склонирует |
| `/vps-new` | `claude-new <имя>` | побочная сессия в текущей папке |
| `/vps-sessions` | `claude-list` | список сессий и память |
| `/vps-close` | `claude-close [имя]` | закрыть сессию |
| `/vps-close-all` | `claude-close-all` | закрыть побочные |
| `/vps-close-everything` | `claude-close-everything` | закрыть всё, кроме `vps-main` |
| `/vps-ssh` | `claude-ssh [имя]` | команда входа в терминал сессии |

Закрытие выгружает сессию из памяти, файлы остаются. Побочные сессии старше 7 дней
закрываются сами. Войти в живой терминал: `ssh dev@<IP> -t 'tmux attach -t <сессия>'`
(выйти не убивая — `Ctrl+B`, затем `D`).

### Сессии переживают перезагрузку и падения

Открытые сессии числятся в реестре `~/.claude/open-sessions/` — по файлу на сессию
(рабочая папка + id последнего диалога, id обновляется у живых сессий раз в 5 минут).

- **Перезагрузка сервера** — `claude-ops.service` поднимает `vps-main` и сразу
  вызывает `claude-restore --boot`: сессии из реестра возвращаются **с продолжением
  прежнего диалога** (`--resume` по записанному id, иначе `--continue` последним
  диалогом папки, иначе чистый старт).
- **Падение сессии** (OOM, краш) — таймер `claude-restore.timer` раз в 5 минут
  поднимает всё, что числится в реестре, но не живо. `claude-list` показывает такие
  сессии отдельно; поднять немедленно — `claude-restore`.
- **Закрытие вручную** снимает сессию с реестра, так что закрытое не возвращается.
  То же делает автоочистка простаивающих.

Страховка от цикла: если сессия падает **3 раза за час**, сторож перестаёт её
поднимать и пишет об этом в журнал — значит, ломается она сама, а не сервер.
Счётчик обнуляется через час или сразу при ручном открытии. Сторож также не
запускает новые сессии, когда свободно меньше 800 МБ, — чтобы не добить сервер.

```bash
claude-restore                      # поднять упавшие прямо сейчас
claude-registry list                # что числится открытым
journalctl --user -u claude-restore -e   # журнал подъёмов
```

## Сеть и безопасность

- Наружу открыт **только SSH**; 80/443 закрыты. Проекты доступны с твоих устройств
  через Tailscale по адресу `dev-vps.<tailnet>.ts.net`. Домен, nginx и Let's Encrypt
  не нужны — Tailscale сам выдаёт валидный сертификат.
- SSH только по ключу, пароли выключены, fail2ban.
- **Контейнеры закрыты от интернета правилом в `DOCKER-USER`** (`/etc/ufw/after.rules`).
  Без него база проекта видна из интернета: docker публикует порты мимо UFW, а настройка
  `"ip"` в `daemon.json` действует только на дефолтную bridge-сеть — compose создаёт свою
  и публикует на `0.0.0.0`.
- Каждому проекту выделен блок из 10 портов (`ports/<имя>.env`). Учёт — команда `ports`:
  `ports claim <имя>` бронирует свободный блок, `ports map` показывает занятое/свободное.
  Реестр общий, поэтому забронированное сразу видно всем и коллизий нет. Инфра-диапазон
  `8060-8069` из раздачи исключён.
- **Порты в tailnet — по схеме «порт = порт».** Каждый веб-сервис проекта отдаётся в
  tailnet на том же номере, что и на хосте: `127.0.0.1:8050` → `https://dev-vps.<tailnet>.ts.net:8050`.
  Один номер на сервис, совпадает с `ports map`. Делает это `ports-web` (ставит `setup-dev.sh`,
  таймер раз в минуту): по образу контейнера отличает веб от БД/redis (последние наружу не
  отдаются), сам подхватывает новые проекты и снимает ушедшие. Базы наружу по-прежнему
  закрыты — к ним ходят через DbGate.
- **Дашборд** — страница со ссылками на все занятые порты (проект, имя сервиса, описание),
  `https://dev-vps.<tailnet>.ts.net:8062`. Генерит `ports-web`, обновляется автоматически.
  Это точка входа: одну ссылку в закладки — остальное кликом.
- **Dozzle** (`:8060`) — веб-обзор docker-контейнеров и логов, только просмотр (docker-сокет
  смонтирован read-only). **DbGate** (`:8061`) — веб-клиент баз всех проектов: подключения
  сохранены в docker-volume `dbgate-data`, порты баз наружу не открывает — цепляется к
  docker-сетям проектов и ходит к БД по **имени контейнера**. Оба — инфра-сервисы, слушают
  `127.0.0.1`, в tailnet их выводит тот же `ports-web`.

## Переезд на новый сервер

Повтори «Установку» и «Первый проект» — это вся процедура. Отдельно донеси руками:

- **секреты проектов** — ключи API, токены платных пакетов, конфиги Firebase; в git их нет;
- **данные dev-баз** — живут в docker-volume'ах, восстанавливаются миграциями и сидами.

## Файлы

```
~/vps/          этот репозиторий: скрипты, порты, контракт.
                Он же — рабочая папка управляющей сессии, роль в CLAUDE.md
/projects/      код проектов + CLAUDE.md с правилами сервера
~/.local/bin/   команды claude-*
~/.claude/open-sessions/   реестр открытых сессий (для восстановления)
```

## Если что-то сломалось

- **SSH не пускает** — проверь бан: `sudo fail2ban-client status sshd`, разбан:
  `sudo fail2ban-client set sshd unbanip <IP>`. Вход всегда по ключу, пароли не включай.
- **Совсем нет доступа** — консоль VNC в панели хостинга работает мимо SSH и firewall.
- **Скилл из репозитория не виден** — репозиторий склонировали в уже открытую сессию;
  переоткрой проект (`claude-close X` → `claude-project X`).
- **Архивация в приложении не освобождает память** — она убирает карточку, процесс живёт.
  Освобождает только `claude-close`.
- **Сессия висит в приложении и не отвечает** — процесс умер (чаще всего OOM), карточка
  осталась. Проверь: `claude-list` (упавшие показаны отдельно) и
  `journalctl -b -1 | grep -i oom`. Сторож поднимет её сам в течение 5 минут,
  вручную — `claude-restore`.
- **Упавшая сессия не поднимается** — сторож мог её заглушить после трёх падений за час:
  `journalctl --user -u claude-restore -e`. Разберись с причиной и открой вручную
  (`claude-project X` / `claude-new X`) — это сбросит счётчик.
