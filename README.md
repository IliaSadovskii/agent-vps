# VPS Bootstrap — Claude Code на своём сервере

Разворачивает Ubuntu VPS для работы с Claude Code через мобильное приложение:
сессии живут на сервере постоянно, доступны с телефона, переживают перезагрузку.
Приложение — окно в процессы на VPS; код и файлы остаются на сервере.

## Запуск

Скрипт сам определяет режим по пользователю:

```bash
sudo bash vps-bootstrap.sh   # под root: настройка сервера
bash vps-bootstrap.sh        # под dev:  автозапуск сессии
bash vps-bootstrap.sh --help # памятка
```

Идемпотентный — повторный запуск безопасен.

### Первая настройка

```bash
sudo bash vps-bootstrap.sh          # 1. под root: пользователь, пакеты, безопасность

ssh dev@<IP> && source ~/.bashrc     # 2. под dev: авторизация в браузере (по подписке)
claude                               #    вход по ПОДПИСКЕ, довести до конца, /exit
gh auth login && gh auth setup-git   #    для приватных репозиториев

bash vps-bootstrap.sh                # 3. под dev: включить автозапуск
bash dev-env.sh                      # 4. под dev: окружение для разработки
sudo tailscale up --hostname=dev-vps #    авторизация в браузере по ссылке
```

После этого `vps-main` появится в приложении (раздел Code).

## Что ставит скрипт

Node.js 22, Claude Code, gh (GitHub CLI), git, tmux и утилиты.
Создаёт пользователя `dev` (passwordless sudo), папки `~/ops` и `/projects`.
Безопасность: SSH только по ключу (root — по ключу, не по паролю), fail2ban, UFW
(порты 22/80/443 — `dev-env.sh` потом закрывает 80/443 за ненадобностью).

Авторизация — по подписке (Claude Pro/Max), не по API-ключу. Нужен именно
`claude` (сохраняет вход в `~/.claude/.credentials.json`), не `setup-token`.

## Сессии

Три типа, различаются по имени в приложении:

| Имя | Роль | Где живёт |
|---|---|---|
| `vps-main` | управление сервером, не закрывается | `~/ops` |
| `vps-<имя>` | побочная задача (управляющая или дочерняя) | текущая папка |
| `proj-<имя>` | главная сессия проекта | `/projects/<имя>` |

`~/ops` — управление сервером, `/projects` — код проектов.

## Команды

Каждая возможность вызывается тремя способами: слэш-командой в сессии,
обычной фразой (агент поймёт), или CLI-утилитой в терминале.

| Слэш | Фраза | CLI | Действие |
|---|---|---|---|
| `/vps-new` | «создай сессию для X» | `claude-new <имя>` | побочная сессия в текущей папке |
| `/vps-project` | «создай проект X» | `claude-project <имя> [url]` | проект в `/projects`; с url — клонирует репо |
| `/vps-sessions` | «какие сессии открыты» | `claude-list` | список + память |
| `/vps-close` | «закройся» / «закрой X» | `claude-close [имя]` | закрыть текущую или названную |
| `/vps-close-all` | «закрой лишние» | `claude-close-all` | закрыть побочные (проекты и main остаются) |
| `/vps-close-everything` | «закрой всё» | `claude-close-everything` | закрыть всё, кроме main |
| `/vps-ssh` | «дай ssh-команду» | `claude-ssh [имя]` | строка входа в терминал сессии |

Каждая слэш-команда — отдельный скилл в `~/.claude/skills/vps-*`; он же
срабатывает по фразе. CLI-утилиты (`claude-*` в `~/.local/bin`) делают саму
работу — скиллы их вызывают.

Закрытие сессии не удаляет файлы — только выгружает из памяти. Проект
переоткрывается той же `claude-project <имя>` (код цел). Простаивающие побочные
сессии сами закрываются через 7 дней.

## Работа с GitHub

Через `gh` CLI на сервере (не через UI, как в облачных сессиях). Авторизация
глобальная (`gh auth login` один раз).

Подключить репо: «создай проект shop из github.com/me/shop» → клонирует при
создании. Или голосом внутри: «склонируй сюда github.com/me/shop».

Разработка (агент в bypass-режиме делает всё сам, без запросов, включая
`git push` и `gh pr create`): «сделай фичу X в ветке» → «запушь и создай PR».

## Автоматика

- Автозапуск `vps-main` после перезагрузки (systemd + linger).
- `ExecStartPre` гарантирует единственность `vps-main`.
- При `bash vps-bootstrap.sh` (dev) закрываются ВСЕ сессии и поднимается свежая
  `vps-main` — гарантия актуальных скиллов везде. Проекты переоткрываются вручную.
- Автоочистка побочных сессий старше 7 дней (`MAX_IDLE_DAYS`).

## Подключение к терминалу

Когда нужен полноценный терминал (интерфейс приложения ограничивает):

```bash
ssh dev@<IP> -t 'tmux attach -t <сессия>'   # claude-ssh выдаёт готовую строку
```

Та же живая сессия, что в приложении. Выйти не убивая: `Ctrl+B`, затем `D`.
Нестандартный ключ — пропиши в `~/.ssh/config` на своём компьютере.

## Управление сервисом (под dev)

```bash
systemctl --user status claude-ops    # статус
systemctl --user restart claude-ops   # перезапуск
tmux attach -t claude-ops             # войти в основную сессию
```

## Окружение для разработки (`dev-env.sh`)

Второй скрипт, отдельно от `vps-bootstrap.sh`: тот отвечает за доступ к серверу,
и сломав его правкой, теряешь вход. Здесь — платформа для запуска проектов.

```bash
bash dev-env.sh   # под dev, идемпотентный
```

### Принцип: платформа даёт способность, проект объявляет потребность

Скрипт ставит только то, что общее для любого стека. Языки, рантаймы и базы
данных приходят из репозитория самого проекта — через `docker-compose.yml` и
`.mise.toml`. Поэтому в `dev-env.sh` нет ни одного упоминания конкретного
языка или БД, и новый проект на любом стеке не требует его править.

| Ставится | Зачем |
|---|---|
| **docker + compose** | окружение проекта описано в его же репозитории |
| **tailscale** | единственный вход снаружи, HTTPS-сертификат из коробки |
| **mise** | менеджер версий тулчейнов — там, где контейнер не подходит |

Плюс: swap 4 ГБ, правила firewall и раздача портов проектам.

### Доступ снаружи

Порты наружу не открыты вообще: в интернет смотрит только SSH. Сервер входит в
приватную сеть Tailscale, и проекты доступны с твоих устройств по адресу
`dev-vps.<tailnet>.ts.net`. Домен, nginx и Let's Encrypt не нужны — Tailscale
сам выдаёт валидный сертификат.

**Важно про Docker и firewall.** Docker публикует порты, вписывая правила прямо
в iptables до цепочек UFW, поэтому `ufw default deny incoming` контейнеров не
касается — без защиты база проекта видна из интернета. Настройка `"ip"` в
`daemon.json` помогает лишь частично: она действует только на дефолтную
bridge-сеть, а compose создаёт для каждого проекта свою. Настоящая защита —
правило в цепочке `DOCKER-USER` (`/etc/ufw/after.rules`): пропускаем ответы на
исходящие соединения, трафик из tailnet и между контейнерами, остальное
отбрасываем. Правило не привязано к имени сетевого интерфейса, поэтому работает
и на другом сервере.

### Порты

Каждому проекту выделен блок из 10 портов. Раскладка блока — в `ports/<имя>.env`
этого репозитория; `dev-env.sh` дописывает её в `.env` проекта и проверяет, что
проекты не пересекаются и не вылезают за свой блок. Файлы лежат здесь, потому
что `.env` проектов не в git — иначе после переезда раскладку пришлось бы
вспоминать.

Новый проект: создать `ports/<имя>.env`, взять свободный десяток, запустить
`dev-env.sh`.

### Требования к проектам

Описаны в [docs/PROJECT-CONTRACT.md](docs/PROJECT-CONTRACT.md) — там же готовое
задание для агента, чтобы он привёл проект к контракту сам. Коротко: `Makefile`
с целями `up`/`down`/`test`, порты через переменные, `.env.example` без секретов.

## Переезд на новый сервер

```bash
sudo apt install -y git gh && gh auth login
git clone https://github.com/IliaSadovskii/vps.git && cd vps

sudo bash vps-bootstrap.sh           # сервер, пользователь, Claude Code
bash vps-bootstrap.sh                # автозапуск сессии (под dev)
bash dev-env.sh                      # платформа разработки
sudo tailscale up --hostname=dev-vps # авторизация по ссылке в браузере

claude-project <имя> <git-url>       # склонировать проект
bash dev-env.sh                      # разложить ему порты
cd /projects/<имя> && make up
```

Что **не** переезжает и требует ручного участия:

- **данные dev-баз** — лежат в docker-volume'ах; восстанавливаются средствами
  самого проекта (миграции и сиды);
- **секреты проектов** — токены платных пакетов, ключи API, конфиги Firebase.
  В git их нет намеренно; держи отдельно и доноси руками в `.env`;
- **авторизации** — Claude Code, `gh`, Tailscale: три входа в браузере.

## Файлы на сервере

```
/home/dev/ops/            vps-main + CLAUDE.md (роль управляющего агента)
/home/dev/vps/            этот репозиторий (скрипты и порты проектов)
/home/dev/.local/bin/     команды claude-*
/home/dev/.claude/        settings.json, credentials, skills, история сессий
/projects/<имя>/          код проектов
```

## Аварийный доступ

Если SSH недоступен: панель FreakHosting → VPS → Options → VNC → консоль под root
(работает мимо firewall и SSH).

## Частые проблемы

**SSH refused / Permission denied** — проверь через `vps-main`: конфиг
(`sudo sshd -T | grep permitrootlogin` должен быть `prohibit-password`) и бан
(`sudo fail2ban-client status sshd`, разбан: `... set sshd unbanip <IP>`). Вход
всегда по ключу — под root и dev. Пароли не включай (это защита).

**Скилл из репозитория не виден** — репо склонировали в уже работающую сессию.
Клонируй сразу: «создай проект X из <url>». Если попал — `/reload-skills`, иначе
переоткрой проект (`claude-close X` → `claude-project X`).

**Архивация в приложении не освобождает память** — она убирает карточку, процесс
на VPS живёт. Освобождает только закрытие (`claude-close` / «закройся»).

**`dpkg lock`** — прерванный apt. Проверь `ps aux | grep apt`; если процесс мёртв,
сними локи и `sudo dpkg --configure -a`.

## Настройки (в начале скрипта)

```bash
DEV_USER="dev"            PROJECTS_DIR="/projects"
OPS_DIR="/home/dev/ops"   TIMEZONE="Asia/Tbilisi"
```

Автоочистка: `MAX_IDLE_DAYS=7` в юните `claude-cleanup.service`.
