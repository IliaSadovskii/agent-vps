# vps — сервер для разработки с Claude Code

Превращает чистый Ubuntu VPS в машину, где **агенты Claude Code живут постоянно** и
разрабатывают твои проекты. Сессии переживают перезагрузку, доступны из мобильного
приложения и по SSH. Проекты поднимаются в docker, наружу не торчат.

Задумано так: одна управляющая сессия обслуживает сервер, у каждого проекта своя
сессия в своей папке, все они работают параллельно и не мешают друг другу.

## Как устроено

Три слоя, каждый ставится своим скриптом или приходит из репозитория проекта:

| Слой | Что даёт | Откуда |
|---|---|---|
| **Доступ** | пользователь `dev`, SSH по ключу, Claude Code, сессии | `vps-bootstrap.sh` |
| **Платформа** | docker, tailscale, mise, firewall, порты | `dev-env.sh` |
| **Проект** | своя БД, свой рантайм, свои версии | `docker-compose.yml`, `.mise.toml` проекта |

Скрипта два намеренно: первый отвечает за вход на сервер, и его поломка стоит доступа.
Второй меняется чаще — пусть его правки не могут уронить SSH.

Главный принцип: **платформа даёт способность, проект объявляет потребность.** На хост
не ставится ни одного языка и ни одной БД — всё приходит из репозитория проекта. Поэтому
проект на любом стеке не требует править инфраструктуру.

## Установка на чистый VPS

Нужен Ubuntu 22.04/24.04 и SSH-ключ у root.

```bash
# 1. под root: пользователь, пакеты, Claude Code, безопасность
ssh root@<IP>
git clone https://github.com/IliaSadovskii/vps.git && cd vps
sudo bash vps-bootstrap.sh

# 2. под dev: три авторизации в браузере
ssh dev@<IP> && source ~/.bashrc
claude                                # вход по ПОДПИСКЕ (не по API-ключу), довести до конца, /exit
gh auth login && gh auth setup-git    # для приватных репозиториев

# 3. под dev: автозапуск управляющей сессии
cd ~/vps && bash vps-bootstrap.sh

# 4. под dev: платформа разработки
bash dev-env.sh
sudo tailscale up --hostname=dev-vps  # авторизация по ссылке, которую он напечатает
```

Оба скрипта идемпотентны — повторный запуск безопасен.

После этого поставь [клиент Tailscale](https://tailscale.com/download) на ноутбук и телефон
и войди тем же аккаунтом: сервер наружу закрыт, и это единственный путь к проектам.
В [консоли Tailscale](https://login.tailscale.com) включи **Serve** — один раз, чтобы
проекты открывались по HTTPS.

Управляющая сессия `vps-main` появится в приложении Claude (раздел Code).

## Первый проект

```bash
claude-project shop https://github.com/me/shop   # склонировать и открыть сессию
```

Если проекту нужны порты — выдели ему блок (в репозитории `vps`):

```bash
cat > ports/shop.env <<'EOF'
# shop — блок 8030-8039
APP_PORT=8030
DB_PORT=8031
EOF
bash dev-env.sh          # проверит пересечения и пропишет порты в .env проекта
```

Дальше работай в сессии проекта: `make up`, `make test`.

## Правила проектов

Проекты обязаны соблюдать [контракт](docs/PROJECT-CONTRACT.md): `Makefile` с целями
`up`/`down`/`test`, порты через переменные, `.env.example` без секретов.

**Агенты узнают правила сами.** Claude Code читает `CLAUDE.md` вверх по дереву каталогов,
поэтому `dev-env.sh` кладёт правила в `/projects/CLAUDE.md` — и любая сессия проекта видит
их автоматически, вместе с личным `CLAUDE.md` проекта. Копировать ничего не нужно.
Текст правил — в `templates/projects-CLAUDE.md`.

Чтобы агент привёл проект к контракту, в его сессии достаточно сказать:
«приведи проект к контракту сервера» — путь к документу он уже знает.

## Сессии

| Имя | Роль | Папка |
|---|---|---|
| `vps-main` | управление сервером, не закрывается | `~/ops` |
| `proj-<имя>` | главная сессия проекта | `/projects/<имя>` |
| `vps-<имя>` | побочная задача | текущая папка |

Каждая команда работает тремя способами: слэш-командой, обычной фразой или в терминале.

| Слэш | CLI | Действие |
|---|---|---|
| `/vps-project` | `claude-project <имя> [url]` | проект в `/projects`, с url — склонирует |
| `/vps-new` | `claude-new <имя>` | побочная сессия в текущей папке |
| `/vps-sessions` | `claude-list` | список сессий и память |
| `/vps-close` | `claude-close [имя]` | закрыть сессию |
| `/vps-close-all` | `claude-close-all` | закрыть побочные |
| `/vps-close-everything` | `claude-close-everything` | закрыть всё, кроме `vps-main` |
| `/vps-ssh` | `claude-ssh [имя]` | команда входа в терминал сессии |

Закрытие выгружает сессию из памяти, файлы остаются. Побочные сессии старше 7 дней
закрываются сами. Автозапуск `vps-main` после перезагрузки — через systemd.

Подключиться к живому терминалу сессии: `ssh dev@<IP> -t 'tmux attach -t <сессия>'`
(выйти не убивая — `Ctrl+B`, затем `D`).

## Сеть и безопасность

- Наружу открыт **только SSH**. Порты 80/443 закрыты, проектам они не нужны.
- Проекты доступны с твоих устройств через Tailscale по адресу `dev-vps.<tailnet>.ts.net`.
  Домен, nginx и Let's Encrypt не нужны — Tailscale сам выдаёт валидный сертификат.
- SSH только по ключу, пароли выключены, fail2ban.
- **Контейнеры закрыты от интернета правилом в `DOCKER-USER`** (`/etc/ufw/after.rules`).
  Это не перестраховка: docker публикует порты мимо UFW, а настройка `"ip"` в
  `daemon.json` действует только на дефолтную bridge-сеть — compose создаёт свою и
  публикует на `0.0.0.0`. Без правила база проекта видна из интернета.
- Каждому проекту выделен блок из 10 портов (`ports/<имя>.env`), пересечения проверяются.

## Переезд на новый сервер

Повтори «Установку» и «Первый проект» — это и есть вся процедура. Отдельно нужно донести:

- **секреты проектов** — ключи API, токены платных пакетов, конфиги Firebase; в git их нет;
- **данные dev-баз** — живут в docker-volume'ах, восстанавливаются миграциями и сидами.

## Файлы

```
~/vps/          этот репозиторий: скрипты, порты проектов, контракт
~/ops/          папка управляющей сессии
/projects/      код проектов + CLAUDE.md с правилами сервера
~/.local/bin/   команды claude-*
```

## Если что-то сломалось

- **SSH не пускает** — проверь бан: `sudo fail2ban-client status sshd`, разбан:
  `... set sshd unbanip <IP>`. Вход всегда по ключу; пароли не включай.
- **Совсем нет доступа** — консоль VNC в панели хостинга работает мимо SSH и firewall.
- **Скилл из репозитория не виден** — репозиторий склонировали в уже открытую сессию;
  переоткрой проект (`claude-close X` → `claude-project X`).
- **Архивация в приложении не освобождает память** — она убирает карточку, процесс живёт.
  Освобождает только `claude-close`.
